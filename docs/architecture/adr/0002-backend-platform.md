# ADR-0002: Платформа бэкенда

Статус: Принято

Дата: 29 июля 2026 года

Обновлено: 31 июля 2026 года

## Контекст

Цель проекта — не только создать pet-проект, но и проверить агентскую разработку
на стеке, близком к рабочему контексту. Нагрузка однопользовательская, поэтому
реактивная модель не даёт достаточной пользы для своей сложности.

## Решение

- Язык бэкенда — Kotlin 2.2.20.
- Серверный фреймворк — Kora 1.2.18 из стабильной ветки 1.x.
- Java toolchain — Java 25; JVM bytecode target для Kotlin и Java — 24.
- Gradle Wrapper — 9.6.1.
- Обработка Kotlin-аннотаций выполняется KSP `2.2.20-2.0.4` во временном
  режиме KSP1 (`ksp.useKSP2=false`). KAPT не используется.
- Версии plugins и библиотек централизуются в version catalog.
- Запросы с блокирующим I/O выполняются на виртуальных потоках.
- Явная асинхронность и реактивный стек не применяются без отдельной
  необходимости.
- Доступ к данным синхронный, через JDBC, Kora JDBC repositories и явный SQL.
- Бизнес-арифметика использует `BigDecimal`; `float` и `double` запрещены для
  финансовых расчётов.

Зависимости обновляет Renovate или Dependabot. Изменения не сливаются
автоматически и обязаны пройти полную CI-сборку. Patch/minor обновления являются
обычными техническими изменениями. Major-версии Java, Kotlin, Kora, Gradle,
TypeSpec и генераторов рассматриваются отдельно. Java toolchain меняется только
явным решением.

## Последствия

- Код остаётся знакомым Java/Kotlin-разработчику и удобным для пошаговой отладки.
- Внешние вызовы и JDBC могут выглядеть синхронно без блокировки platform threads.
- Версии зафиксированы для воспроизводимости агентской разработки.
- Переход на Kora 2.x или реактивный persistence потребует отдельной оценки.

## Временный режим KSP1

Kora 1.2.18 сохраняет KSP symbols между раундами обработки. KSP2 инвалидирует
эти symbols после изменения PSI, поэтому чистая сборка падает в
`KoraAppProcessor.parseNone` с `KaInvalidLifetimeOwnerAccessException`.
Поведение воспроизведено на KSP 2.2.20-2.0.4, 2.3.7 и 2.3.10.

KSP1 остаётся временной совместимой конфигурацией. Из-за его ограничений Kotlin
зафиксирован на 2.2.20, а JVM bytecode target — на 24. Java 25 продолжает
использоваться как toolchain. Предупреждение KSP1 об устаревании считается
известным и не является основанием возвращаться на KAPT.

Переход на KSP2 выполняется, когда одновременно выполнены следующие условия:

- стабильная совместимая версия Kora 1.x больше не сохраняет KSP symbols между
  раундами либо обновление Kora отдельно принято после оценки;
- выбранная версия KSP2 поддерживает принятую версию Kotlin и Java 25;
- удаление `ksp.useKSP2=false` не требует локальных патчей Kora processors;
- чистые `generateOpenApi`, `check` и `build`, backend/frontend-тесты и
  runtime smoke test проходят на Windows и в Linux CI;
- version catalog, ADR и документация локального запуска обновлены вместе с
  Kotlin, KSP и JVM bytecode target.

## Рассмотренные альтернативы

- R2DBC и реактивный стек отклонены: нагрузка не оправдывает дополнительную
  модель исполнения.
- Kora 2.x не выбран из-за предварительного статуса на момент решения.
- Spring Boot не выбран, поскольку Kora ближе к рабочему стеку и целям
  исследования.
