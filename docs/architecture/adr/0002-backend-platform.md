# ADR-0002: Платформа бэкенда

Статус: Принято  
Дата: 29 июля 2026 года

## Контекст

Цель проекта — не только создать pet-проект, но и проверить агентскую разработку
на стеке, близком к рабочему контексту. Нагрузка однопользовательская, поэтому
реактивная модель не даёт достаточной пользы для своей сложности.

## Решение

- Язык бэкенда — Kotlin 2.4.10.
- Серверный фреймворк — Kora 1.2.18 из стабильной ветки 1.x.
- Java toolchain — Java 25.
- Gradle Wrapper — 9.6.1.
- Версии plugins и библиотек централизуются в version catalog.
- Запросы с блокирующим I/O выполняются на виртуальных потоках.
- Явная асинхронность и реактивный стек не применяются без отдельной
  необходимости.
- Доступ к данным синхронный, через JDBC, Kora JDBC repositories и явный SQL.
- Бизнес-арифметика использует `BigDecimal`; `float` и `double` запрещены для
  финансовых расчётов.

Зависимости обновляет Renovate или Dependabot. Изменения не сливаются
автоматически и обязаны пройти полную CI-сборку. Patch/minor обновления являются
обычными техническими изменениями. Major-версии Java, Kotlin, Kora, Gradle,
TypeSpec и генераторов рассматриваются отдельно. Java toolchain меняется только
явным решением.

## Последствия

- Код остаётся знакомым Java/Kotlin-разработчику и удобным для пошаговой отладки.
- Внешние вызовы и JDBC могут выглядеть синхронно без блокировки platform threads.
- Версии зафиксированы для воспроизводимости агентской разработки.
- Переход на Kora 2.x или реактивный persistence потребует отдельной оценки.

## Рассмотренные альтернативы

- R2DBC и реактивный стек отклонены: нагрузка не оправдывает дополнительную
  модель исполнения.
- Kora 2.x не выбран из-за предварительного статуса на момент решения.
- Spring Boot не выбран, поскольку Kora ближе к рабочему стеку и целям
  исследования.
