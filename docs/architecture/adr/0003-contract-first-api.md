# ADR-0003: Contract-first API и финансовые значения

Статус: Принято  
Дата: 29 июля 2026 года

## Контекст

Фронтенд и бэкенд должны иметь строго типизированную границу. JavaScript
`number` не способен безопасно представлять произвольные десятичные финансовые
значения, а независимо описанные DTO быстро расходятся.

## Решение

TypeSpec является первичным исходным текстом HTTP-контракта:

```text
TypeSpec → OpenAPI 3.0 → Kotlin/Kora server API
                       → TypeScript client
```

- Для операций задаются стабильные `operationId`.
- Объектные схемы закрыты для неизвестных полей.
- Сгенерированный код вручную не редактируется.
- TypeSpec и `api/generated/openapi.yaml` хранятся в Git.
- Kotlin API-типы и TypeScript-клиент генерируются в build-каталоги и в Git не
  добавляются.
- CI повторно генерирует OpenAPI и проверяет отсутствие diff, а также публикует
  его как build artifact.

Деньги, цены, доли и комиссии передаются как канонические десятичные строки:

```text
0
12
12.34
-0.125
```

Разделитель — точка, экспоненциальная форма не допускается. На бэкенде строки
преобразуются в `BigDecimal`, на фронтенде — в `decimal.js`. Авторитетные
расчёты выполняет бэкенд; фронтенд отвечает за ввод, показ и предварительную
проверку.

## Последствия

- Изменение TypeSpec обязательно сопровождается обновлением сохранённого
  OpenAPI.
- Финансовые DTO не используют JSON `number`.
- Генераторы являются частью воспроизводимой сборки.
- Контракт можно рецензировать и использовать без установки TypeSpec toolchain.

## Рассмотренные альтернативы

- Code-first отклонён из-за риска расхождения клиентов и серверных DTO.
- JSON `number` отклонён из-за бинарного представления JavaScript.
- Хранение всего generated-кода в Git отклонено из-за шума и дублирования.
- Генерация OpenAPI только в CI отклонена: сохранённый файл упрощает review и
  использование внешними инструментами.
