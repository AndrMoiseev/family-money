# ADR-0009: Внешние интеграции MVP

Статус: Принято  
Дата: 29 июля 2026 года

## Контекст

Ручная работа является обязательным P0-сценарием. Автоматические цены имеют
приоритет P1, а синхронизация брокерских позиций не должна задерживать выпуск.
Интеграция не должна получать возможность совершать сделки или неявно менять
фактическое состояние.

## Решение

Единственная планируемая внешняя интеграция MVP — T-Invest API:

- сначала реализуется получение цен через `MarketDataService`;
- синхронизация портфеля Т-Банка добавляется после цен, если не задерживает P0;
- используется только read-only token;
- full-access tokens, orders и любые торговые операции запрещены;
- обновление явно запускается пользователем, background scheduler не требуется;
- перед применением позиций пользователь видит diff и подтверждает изменение;
- сбой не повреждает сохранённые данные и не блокирует ручной ввод;
- tokens передаются runtime secrets и не хранятся в Git или открытом виде в БД.

Интеграции скрыты за независимыми ports:

```kotlin
interface MarketPriceProvider
interface BrokerPortfolioProvider
```

Ручное изменение цен, позиций и свободных денег работает независимо от состояния
адаптеров. Интеграция со Сбером, MOEX ISS, импорт брокерских отчётов и другие
поставщики остаются после MVP.

## Последствия

- Один официальный API проверяет архитектуру внешних adapters без создания
  универсальной integration platform.
- T-Invest transport types не проникают в доменную модель.
- Secret с минимальными правами снижает последствия утечки.
- Синхронизация всегда отделена от применения изменений.

## Рассмотренные альтернативы

- Одновременная поддержка нескольких брокеров отклонена как риск для сроков MVP.
- MOEX ISS не выбран первым источником из-за условий использования биржевой
  информации и отсутствия синхронизации портфеля.
- Сбер отложен: подходящего официального retail brokerage API не подтверждено.
- Автоматическое исполнение сделок исключено из MVP.
